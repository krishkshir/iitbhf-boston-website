The one constitution divergence

§4 says "forwards to Home." This spec renders Home at the URL instead — no redirect. needs a §4 amendment

docs/CONSTITUTION.md §4 describes /from/{event} as a namespace that "logs the traffic source and forwards to Home." §5 makes the scan greeting ("You scanned us at Colors of India.") the site's one signature design element.

On a purely static build (output: 'static', no server), an actual forward means a second HTTP round trip, and the greeting has to be assembled from a query parameter client-side — i.e. it silently disappears for any visitor with JavaScript blocked, slow, or a locked-down phone. That cost falls on exactly the visitor §2 names as highest-value: outdoors, on a phone, on cellular, scanning a printed flyer.

This spec instead has getStaticPaths generate a full Home page at /from/colors-of-india, with the greeting baked into the HTML. One request, zero JS dependency, and Cloudflare Web Analytics attributes the scan by path — so the §1 success criterion ("≥50% of scans convert to a visit") reads directly off one path's pageview count instead of being reconstructed from a two-hop funnel. See §/from/{slug} in detail for the full design and the three additions (canonical/noindex, no URL rewrite, build-time slug assertion) that make it safe.

This serves §4's intent (traffic source is measurable, visitor lands on Home) while departing from its literal wording. Per the constitution's own preamble — "if this file and a conversation disagree, update this file" — the implementation commit should amend §4's sentence to describe this mechanism, not leave the old wording standing next to different code.

Content collections

src/content.config.ts

import { defineCollection, z } from 'astro:content';
import { glob } from 'astro/loaders';

const BRANCHES = [
  'Aero','ChemE','Chemistry','CivilE','CSE','EE','EP','Humanities',
  'IDC','Math','MechE','MetE','Physics','SJMSOM','Other',
] as const;

const events = defineCollection({
  loader: glob({ pattern: '**/[^_]*.md', base: './src/content/events' }),
  schema: ({ image }) => z.object({
    title: z.string(),
    date: z.coerce.date(),
    datePrecision: z.enum(['day', 'month']).default('day'),
    location: z.string(),                       // "Lexington, MA"
    summary: z.string().max(200),
    coHosts: z.array(z.string()).default([]),   // ["IIT AGNE"] -> co-host flag, §7
    openToPublic: z.boolean().default(true),    // §1 content policy is explicit about this
    rsvpUrl: z.string().url().optional(),
    heroImage: image().optional(),
    heroImageAlt: z.string().optional(),
    draft: z.boolean().default(false),
  }).refine(d => !d.heroImage || !!d.heroImageAlt, {
    message: 'heroImageAlt is required when heroImage is set',
    path: ['heroImageAlt'],
  }),
});

const ec = defineCollection({
  loader: glob({ pattern: '**/[^_]*.md', base: './src/content/ec' }),
  schema: ({ image }) => z.object({
    name: z.string(),
    role: z.enum(['President','Vice President','Secretary','Treasurer','Trustee','Member']),
    order: z.number().int(),                    // explicit display order; President = 10
    batchYear: z.number().int().min(1958).max(2100),
    branch: z.enum(BRANCHES),
    bio: z.string().max(160),                   // "one-line bio" per §4, enforced as one line
    linkedin: z.string().url().optional(),
    photo: image().optional(),                  // absent -> initials monogram, §7 photo-rights gate
  }),
});

export const collections = { events, ec };

Three schema decisions worth explaining, not just stating

  • datePrecision exists because §4's launch content is month-only ("Diwali Meet (Oct 2025)"). Without it the site invents a day-of-month — and §5 makes dates the structural marker of the whole events archive, so a fabricated date is a content-integrity bug, not a cosmetic one.
  • batchYear as a full year, not '10 — '82 and '10 sort wrong as two-digit strings, and the EC spans '82–'10 per §2. A formatBatch(2010) => "'10" helper in src/data/site.ts does the display for BatchTag.astro.
  • No upcoming flag — derived at build from date >= new Date(). Consequence to accept explicitly: a static build goes stale if an event date passes with no rebuild; note a scheduled rebuild as Phase 1 work in docs/RUNBOOK.md.
The launch state is empty. Today is Aug 2026 and the newest event in §4 is May 2026 — so Home and Events both ship with no upcoming events. That is exactly what the Colors of India visitor sees on Aug 15. Design the empty state as a first-class target (pointing at the mailing list / Get Involved), not as an afterthought.

/from/{slug} in detail

src/data/scan-sources.ts

export interface ScanSource {
  slug: string;        // URL segment; also what qrencode encodes
  name: string;        // "Colors of India" — the greeting subject
  date?: string;        // for the runbook/retrospective, not shown on the page
}
export const scanSources: ScanSource[] = [
  { slug: 'colors-of-india', name: 'Colors of India', date: '2026-08-15' },

src/pages/from/[slug].astro

---
import { scanSources } from '../../data/scan-sources';
import HomeContent from '../../components/HomeContent.astro';
import ScanGreeting from '../../components/ScanGreeting.astro';
import BaseLayout from '../../layouts/BaseLayout.astro';

export function getStaticPaths() {
  if (!scanSources.some(s => s.slug === 'colors-of-india')) {
    throw new Error('scan-sources.ts is missing the printed flyer slug "colors-of-india"');
  }
  return scanSources.map(source => ({ params: { slug: source.slug }, props: { source } }));
}
const { source } = Astro.props;

<BaseLayout title="IITBHF Boston" canonical={new URL('/', Astro.site)} noindex>

  <HomeContent />
</BaseLayout>

Refactor cost of this approach: Home's body moves into src/components/HomeContent.astro; src/pages/index.astro becomes <BaseLayout><HomeContent /></BaseLayout>. That's the whole price — zero content duplication.

Three additions that make this safe

  1. Canonical + noindex. /from/* duplicates Home, so [slug].astro emits <link rel="canonical" href="{site}/"> and <meta name="robots" content="noindex,follow">; add Disallow: /from/ to public/robots.txt. Without this the site ships six near-duplicate pages of the homepage to search engines.
  2. Do not history.replaceState the URL back to /. It races the Cloudflare Web Analytics beacon — if the rewrite wins, the pageview attributes to / and the flyer measurement is destroyed. Leaving /from/colors-of-india visible is also on-brand: §5 lists "QR source slugs" as a Plex Mono data role.
  3. Build-time assertion on the printed slug — already in the getStaticPaths snippet above. Two hundred printed flyers pointing at a 404 is the single highest-cost failure available in Phase 0; three lines make it impossible.

The printed-URL detail

trailingSlash: 'never' (Astro) + html_handling: "drop-trailing-slash" (wrangler) together make the exact flyer string return 200, not a 308: 

qrencode -l H -s 10 -m 2 -o flyer-qr.png "https://<domain>/from/colors-of-india"

Error-correction level H so the code still scans with a chapter mark overlaid or a scuff on an outdoor table. Verify the encoded string round-trips before the print order (Aug 13, §6) — e.g. scan it yourself, or decode with zbarimg.

Unknown or mistyped slugs hit not_found_handling: "404-page" → src/pages/404.astro, which should read as "that link's a little off — here's the chapter," not a bare not-found message. The only humans who reach it arrived from a printed artifact nobody can fix after the fact.

Analytics honesty: Cloudflare Web Analytics is a JS beacon, so a no-JS visitor is invisible to it — the /from/colors-of-india pageview count is a lower bound on scans, not an exact count. Report it that way in the Phase 2 retrospective (§6).

--crest failing is not a palette bug — it's exactly why §5 restricts it to "hairline rules under section eyebrows only." Make that restriction enforceable in review: a crest rule must be purely decorative, never a focus indicator, a meaningful divider, an icon, or an input border, and must always sit beneath a text eyebrow rendered in --ink.

Visible keyboard focus

  • Global: :focus-visible { outline: 3px solid var(--ink); outline-offset: 2px; } — 15.8:1 against linen, well over the 3:1 non-text minimum.
  • Inside --ink bands, override to outline-color: var(--linen).
  • Never outline: none without an equivalent replacement.
  • Skip-to-content link as the first focusable element in BaseLayout.
  • Minimum 44×44 CSS px tap targets on every link and button (§2's "large tap targets are requirements").

prefers-reduced-motion

Exactly one animation ships: the hero fade (§5). It's guarded by the global rule in global.css shown above. No scroll-triggered effects anywhere.

360px

  • Design and review every page at 360×640 first, then widen — breakpoints only add, never rescue.
  • Specific risks in this content: the batch tag '10 · MechE next to a long name (Shailesh Nirgudkar) — let it wrap to its own line, don't shrink it; the event title Alumni Meet with IIT Bombay Visiting Team — wrap, don't truncate; the mission sentence — check for a one-word orphan line; the greeting band — it's the signature element and must be beautiful at 360px, not merely fit.
  • No horizontal scroll: verify document.documentElement.scrollWidth <= 360 at that viewport.
  • <meta name="viewport" content="width=device-width, initial-scale=1"> with no maximum-scale or user-scalable=no — pinch zoom stays available; the EC skews to batches '82–'10 (§2).

Other §5 rules to enforce in review

  • Structural markers are dates, never decorative 01/02/03 numbering.
  • Prominent iitbombay.org link on every page — implemented once in SiteFooter.astro plus NationalBanner.astro on Home/About/Get Involved, so it can't be forgotten per-page.
  • Semantic landmarks: one <h1> per page, header/nav/main/footer, aria-current="page" on the active nav item.
  • Every image has meaningful alt — the Zod .refine() above turns a missing hero alt into a build error, not a review miss.

Fonts — self-hosted, no first-paint regression

Import the woff2 files directly from the fontsource packages and hand-write @font-face rules in BaseLayout.astro — do not import '@fontsource/zilla-slab' wholesale, since its bundled CSS pulls in every subset it ships (Cyrillic, Greek, Vietnamese) that this site will never render. Latin-only subsets, font-display: swap, explicit unicode-range. Preload exactly the two faces that paint above the fold (Zilla Slab 600, Plex Sans 400); let Plex Sans 600 and Plex Mono load on swap without a preload. Budget: ~120 KB total, same-origin — a Google Fonts CDN would add a DNS + TLS handshake to a second origin, which on congested outdoor cell is exactly the cost §2 says to design against. Cache immutably via public/_headers since Astro hashes the filenames.

Devanagari is deliberately deferred: §5 justifies Plex Sans partly by its Devanagari sibling covering names like "Diwali Mela," but every launch string is Latin transliteration — shipping the Devanagari subset now costs ~40 KB per scan for zero rendered glyphs. Load it only when the first Devanagari string enters a content collection; note the trigger in docs/RUNBOOK.md so it reads as a decision.
